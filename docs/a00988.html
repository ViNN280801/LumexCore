Detailed Description

Represents a single fixed-size memory page used by the XmlAllocator.

Each XmlMemoryPage holds a block of raw memory from which smaller objects (nodes, attributes, strings) are allocated. Pages are linked together to form a chain, managed by an XmlAllocator. It contains pointers to the owning allocator, previous/next pages in the chain, and tracks the amount of memory currently in use (busy_size) and freed (freed_size) within itself.

Note
This is an internal structure fundamental to the XML library's memory management.

LUMEX_PUBLIC_API XmlMemoryPage * XmlMemoryPage::construct ( void * memory)
static

Constructs an XmlMemoryPage object in a pre-allocated memory block.

Parameters
[in]memoryA pointer to the raw memory block where the XmlMemoryPage will be constructed.
Returns
A pointer to the newly constructed XmlMemoryPage object.

This static method initializes the fields of XmlMemoryPage within the provided memory address. All pointers (allocator, prev, next) are set to nullptr, and sizes (busy_size, freed_size) are set to 0. This is essentially a placement-new like operation without actually calling new.

Note
The memory block must be large enough to contain an XmlMemoryPage structure.

◆ freed_size

size_t Lumex::Xml::Memory::XmlMemoryPage::freed_size

The amount of memory that has been deallocated within this page.

This tracks the total size of freed blocks. When freed_size equals busy_size, the page is considered empty and can be returned to the system (unless it's the root page).
