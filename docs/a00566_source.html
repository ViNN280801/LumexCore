521  LUMEX_ATTRIBUTE_NODISCARD (
522  "Return value is the contained error; should always be used.")
523  LUMEX_CONSTEXPR_FUNCTION ErrorType &
524  error () &
525  {
526  // Precondition: !m_has_value.
527  // Violation is UB (undefined behavior) for two reasons:
528  //
529  // 1) Interface-level contract (compatibility with C++23).
530  // In std::expected, error() is an unchecked observer with the
531  // precondition that the object holds an error. If the precondition is
532  // violated, behavior is undefined. Checked access is value(), which
533  // throws bad_expected_access<E>. This library keeps the same model:
534  // error() does not add checks or throws, so it stays noexcept and has
535  // no extra cost.
536  //
537  // 2) Language rules for union (implementation level).
538  // Expected storage is a union: either the value member is active
539  // (or a dummy marker for void success), or m_error is active. If
540  // m_has_value == true, m_error is not active. Accessing an inactive
541  // union member is UB in C++. Therefore reading m_storage.m_error when
542  // m_has_value == true is itself undefined behavior at the language
543  // level.
544  //
545  // Why this method does not throw:
546  // - The method must stay usable in noexcept contexts (destructors, swap,
547  // emergency paths).
548  // - Zero release cost: assert is removed under NDEBUG, with no extra
549  // branches or throws.
550  // - Checked, catchable access is already provided by value() (and a prior
551  // has_value() check).
552  //
553  // Practical consequence:
554  // - In debug, assert fires immediately and shows the contract violation.
555  // - In release the caller is responsible: before calling error() it must
556  // guarantee !has_value() (for example via if (!has_value()) ...).
557  LUMEX_ASSERT (
558  !m_has_value
559  && "Calling error() while value is present is undefined behavior.");
560  return m_storage.m_error;
561  }
