522  LUMEX_ATTRIBUTE_NODISCARD (
523  "Return value is the contained error; should always be used.")
524  LUMEX_CONSTEXPR_FUNCTION ErrorType &
525  error () &
526  {
527  // Precondition: !m_has_value.
528  // Violation is UB (undefined behavior) for two reasons:
529  //
530  // 1) Interface-level contract (compatibility with C++23).
531  // In std::expected, error() is an unchecked observer with the
532  // precondition that the object holds an error. If the precondition is
533  // violated, behavior is undefined. Checked access is value(), which
534  // throws bad_expected_access<E>. This library keeps the same model:
535  // error() does not add checks or throws, so it stays noexcept and has
536  // no extra cost.
537  //
538  // 2) Language rules for union (implementation level).
539  // Expected storage is a union: either the value member is active
540  // (or a dummy marker for void success), or m_error is active. If
541  // m_has_value == true, m_error is not active. Accessing an inactive
542  // union member is UB in C++. Therefore reading m_storage.m_error when
543  // m_has_value == true is itself undefined behavior at the language
544  // level.
545  //
546  // Why this method does not throw:
547  // - The method must stay usable in noexcept contexts (destructors, swap,
548  // emergency paths).
549  // - Zero release cost: assert is removed under NDEBUG, with no extra
550  // branches or throws.
551  // - Checked, catchable access is already provided by value() (and a prior
552  // has_value() check).
553  //
554  // Practical consequence:
555  // - In debug, assert fires immediately and shows the contract violation.
556  // - In release the caller is responsible: before calling error() it must
557  // guarantee !has_value() (for example via if (!has_value()) ...).
558  LUMEX_ASSERT (
559  !m_has_value
560  && "Calling error() while value is present is undefined behavior.");
561  return m_storage.m_error;
562  }
