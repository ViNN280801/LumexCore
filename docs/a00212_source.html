91 // ====================== Static assertions ====================== //
92 // References are forbidden because:
93 // 1. This class (and its specializations) is meant to
94 // own the stored success or error value. If SuccessType or ErrorType were
95 // references, for example `int&`, Expected would not own the object, only
96 // refer to it. That can dangle if the original object referred to by
97 // SuccessType (or ErrorType) is destroyed before Expected.
98 // 2. Union restriction: the C++ standard forbids reference members in a
99 // `union`,
100 // because references are neither movable nor copyable.
101 // 3. C++23 compatibility: std::expected also forbids reference types for
102 // the error parameter for the same reasons. Behavior stays consistent and
103 // predictable.

105 "Expected<T,E>: T must not be a reference");

515 LUMEX_ATTRIBUTE_NODISCARD (
516 "Return value is the contained error; should always be used.")
517 LUMEX_CONSTEXPR_FUNCTION ErrorType &
518 error () &
519 {
520 // Precondition: !m_has_value.
521 // Violation is UB (undefined behavior) for two reasons:
522 //
523 // 1) Interface-level contract (compatibility with C++23).
524 // In std::expected, error() is an unchecked observer with the
525 // precondition that the object holds an error. If the precondition is
526 // violated, behavior is undefined. Checked access is value(), which
527 // throws bad_expected_access<E>. This library keeps the same model:
528 // error() does not add checks or throws, so it stays noexcept and has
529 // no extra cost.
530 //
531 // 2) Language rules for union (implementation level).
532 // Expected storage is a union: either the value member is active
533 // (or a dummy marker for void success), or m_error is active. If
534 // m_has_value == true, m_error is not active. Accessing an inactive
535 // union member is UB in C++. Therefore reading m_storage.m_error when
536 // m_has_value == true is itself undefined behavior at the language
537 // level.
538 //
539 // Why this method does not throw:
540 // - The method must stay usable in noexcept contexts (destructors, swap,
541 // emergency paths).
542 // - Zero release cost: assert is removed under NDEBUG, with no extra
543 // branches or throws.
544 // - Checked, catchable access is already provided by value() (and a prior
545 // has_value() check).
546 //
547 // Practical consequence:
548 // - In debug, assert fires immediately and shows the contract violation.
549 // - In release the caller is responsible: before calling error() it must
550 // guarantee !has_value() (for example via if (!has_value()) ...).
551 LUMEX_ASSERT (
552 !m_has_value
553 && "Calling error() while value is present is undefined behavior.");
554 return m_storage.m_error;
555 }
