99 // Each entry passed to LUMEX_DEFINE_REFLECTED_ENUM is (Name) or (Name, Value), e.g.
100 // LUMEX_DEFINE_REFLECTED_ENUM(Foo, std::uint8_t, (A), (B, 5), (C))
101 // The wrapping parens make every entry ONE macro argument regardless of an
102 // internal comma, so LUMEX_PP_ARG_COUNT below counts entries, not tokens.
103 //
104 // LUMEX_DEFINE_REFLECTED_ENUM always emits toString(EnumName). Display strings
105 // default to the enumerator identifiers (#Name): toString(Foo::B) == "B".
106 //
107 // Custom strings: do NOT also call LUMEX_DEFINE_REFLECTED_ENUM (that would define
108 // toString twice). Use LUMEX_DEFINE_REFLECTED_ENUM_TO_STRING instead:
109 // #define FOO_STRINGS(ENTRY) ENTRY(A, "alpha") ENTRY(B, "beta") ENTRY(C, "charlie")
110 // LUMEX_DEFINE_REFLECTED_ENUM_TO_STRING(Foo, std::uint8_t, FOO_STRINGS, (A), (B, 5), (C))
111 // char const* s = toString(Foo::B); // "beta"
112 // There must be no comma between ENTRY(...) entries. Do not name the X-macro
113 // parameter after an enumerator (ENTRY(X, "ex") is fine; X(X, "ex") is not:
114 // the preprocessor would replace both identifiers). Unlisted enumerators and
115 // non-enumerator values of a fixed underlying type return "<Unknown>" (an
116 // enumerator can still map to "" explicitly via its own X-macro entry - that
117 // is a distinct, deliberate case, not the fallback). The returned pointer is
118 // never null.
119 //
120 // Reflection data is emitted as plain EnumName##Values/First/Size/Last
121 // constants next to the enum itself, NOT as an lumex_enum_traits_t<Enum> specialization.
122 // Two independent reasons rule that out, both stemming from [temp.expl.spec]
123 // (an explicit specialization must be declared in the SAME namespace as its
124 // primary template):
125 // 1. MSVC (C2888) additionally refuses a lambda inside such a specialization
126 // when it is defined inside a namespace - an earlier design built
127 // lumex_enum_traits_t<Enum>::values via `[]{ using enum Enum; return std::array{...}; }()`.
128 // 2. Even lambda-free, LUMEX_DEFINE_REFLECTED_ENUM is meant to be invoked from
129 // inside arbitrary namespaces, or even inside a nested struct/class -
130 // neither is the global scope lumex_enum_traits_t<T> would need, so the
131 // specialization itself would be ill-formed regardless of what is inside it.
132 // `static constexpr` on each generated constant is deliberate: at namespace
133 // scope it just gives ordinary internal linkage (harmless per-TU duplication
134 // of a few small constexpr values); at class scope it is required for the
135 // constant to be a shared class constant rather than a bogus non-static data
136 // member. One spelling, both invocation contexts.
