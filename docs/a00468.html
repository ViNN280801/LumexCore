Detailed Description

Internal detail namespace for platform-specific stacktrace functionalities.

This namespace encapsulates helper functions and constants that are used internally by LumexBasicStacktrace for platform-dependent operations like capturing raw frames and resolving symbol information.

Platform-specific stacktrace capture implementation for POSIX systems.

This function captures the current call stack using the backtrace function. It then converts the raw addresses into a vector of LumexStacktraceEntry objects. It includes logic to handle cases where optimizations might reduce frame count (e.g., Release builds).

Template Parameters
AllocatorThe allocator type for the resulting stacktrace.
Parameters
skipNumber of frames to skip from the top of the call stack.
max_depthMaximum number of frames to capture.
allocThe allocator to use for the internal container.
Returns
A LumexBasicStacktrace containing the captured frames. Returns an empty stacktrace if no frames are captured.
Note
This function is noexcept and designed to be exception-safe.

◆ demangle_symbol()

std::string Lumex::Core::Stacktrace::detail::demangle_symbol ( char const * mangled)

Demangles a C++ mangled symbol name on POSIX systems.

This function uses abi::__cxa_demangle from the GNU C++ ABI library to convert a compiler-mangled C++ symbol name into a human-readable form.

Parameters
mangledThe null-terminated C-string of the mangled symbol name.
Returns
A std::string containing the demangled symbol name. If demangling fails, the original mangled name is returned. Returns an empty string if mangled is nullptr.

Retrieves source file and line number information for a given address using addr2line on POSIX systems.

This function attempts to get more precise source location information by executing the addr2line utility as a subprocess. It parses the output to extract the file path and line number.

Parameters
addressThe void* address of the stack frame to resolve.
fileOutput parameter for the source file path.
lineOutput parameter for the line number.
Returns
True if source information was successfully retrieved, false otherwise.
Note
This function typically works best on Linux systems with binutils installed.
Warning
This method involves spawning a child process (popen), which can be relatively slow and resource-intensive.

Resolves symbol information (function name, source file, line number) for a given address on POSIX systems.

This function uses dladdr to get basic symbol information (module, symbol name) and then attempts to use get_source_info_addr2line for more precise source file and line number information. It demangles C++ symbols.

Parameters
addressThe void* address of the stack frame to resolve.
function_nameOutput parameter for the resolved function name.
source_fileOutput parameter for the source file path.
line_numberOutput parameter for the line number in the source file.
Returns
True if any symbol information was successfully resolved, false otherwise.
Exceptions
Nothing.
